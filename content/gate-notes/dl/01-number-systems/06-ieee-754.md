Every laptop, phone and GPU stores real numbers the same way: the **IEEE-754** standard. Its
single-precision (32-bit) and double-precision (64-bit) formats are what C's `float` and `double`,
Java's `float` and `double` and Python's `float` (double) actually hold. GATE has asked about them in
almost every paper since 2017. In this lesson you learn the two bit layouts, how to turn any hex word
into its value and any value into its hex word, what the reserved patterns mean (zero, infinity, NaN
and the denormals that fill the gap around zero), the exact largest and smallest values, how precise
a float really is, and why you can compare two floats by comparing their bits.

## Where this fits

[Lesson 5](lesson:floating-point-basics) built the general machine: a sign, a biased exponent and a
hidden-bit significand. IEEE-754 is that machine with the field widths fixed, the bias fixed at
$2^{k-1} - 1$, and the two end exponent fields reserved for special values. [Lesson 7](lesson:floating-point-arithmetic)
then adds, multiplies and rounds these numbers.

## The two layouts

:::intuition{#layout-intuition title="Three fields, packed for sorting" depth="standard"}
An IEEE word is Lesson 5's floating-point number with every choice already made. The sign comes
first, then the exponent, then the fraction, because that order lets a plain integer comparison sort
positive floats (the [comparison section](#compare-bits) proves it). The exponent is biased so that
the all-zero field is the tiniest scale, and the significand has a hidden 1, so all 23 (or 52)
fraction bits carry information.
:::

:::definition{#ieee-layout term="IEEE-754 binary32 (single) and binary64 (double)" depth="quick"}
| | Single (`float`) | Double (`double`) |
|:--|:--|:--|
| Total bits | 32 | 64 |
| Sign $s$ | 1 bit (bit 31) | 1 bit (bit 63) |
| Exponent field $e$ | 8 bits (30–23) | 11 bits (62–52) |
| Fraction field $f$ | 23 bits (22–0) | 52 bits (51–0) |
| Bias | 127 | 1023 |
| Significant bits $p$ | 24 (hidden 1 + 23) | 53 (hidden 1 + 52) |

For every **normal** pattern ($1 \le e \le 254$ in single, $1 \le e \le 2046$ in double)

$$
x = (-1)^{s} \times 1.f \times 2^{\,e - \text{bias}} .
$$

The end fields, $e = 0$ and $e$ all ones, are reserved for zero, denormals, infinity and NaN (below).
:::

:::viz{#layout-viz spec="ieee-layout" mode="animate" depth="standard"}
:::

:::derivation{#why-127 of="the bias 2^(k−1) − 1 and the normal exponent range" depth="standard"}
With $k = 8$ the field runs $0 \dots 255$. Reserving $0$ and $255$ leaves $1 \dots 254$ for normal
numbers. With bias $127 = 2^{7} - 1$ the true exponents are

$$
E = e - 127 \in \{1 - 127, \dots, 254 - 127\} = \{-126, \dots, 127\}.
$$

Why 127 and not 128? With 127 the range is almost symmetric, and slightly tilted toward large
values: the reciprocal of the smallest normal, $1/2^{-126} = 2^{126}$, is still a normal number, so
$1/x$ never overflows for a normal $x$. With bias 128 the range would be $-127 \dots 126$ and
$1/2^{-127} = 2^{127}$ would sit right at the top.

For double, $k = 11$: bias $2^{10} - 1 = 1023$ and $E \in \{-1022, \dots, 1023\}$.

**Sanity check.** $1.0 = 1.0 \times 2^{0}$ must have $e = 127 = 0111\,1111$, so 1.0 is
`0x3F800000`: $0\ 01111111\ 000\ldots0$ regrouped is $0011\,1111\,1000\,0000\ldots$.
:::

:::table{#ieee-params title="The numbers worth memorising" depth="quick"}
| Quantity | Single | Double |
|:--|:--|:--|
| Normal exponents $E$ | $-126 \dots 127$ | $-1022 \dots 1023$ |
| Largest finite | $(2 - 2^{-23})\,2^{127} \approx 3.40 \times 10^{38}$ | $(2 - 2^{-52})\,2^{1023} \approx 1.80 \times 10^{308}$ |
| Smallest positive normal | $2^{-126} \approx 1.18 \times 10^{-38}$ | $2^{-1022} \approx 2.23 \times 10^{-308}$ |
| Smallest positive denormal | $2^{-149} \approx 1.40 \times 10^{-45}$ | $2^{-1074} \approx 4.94 \times 10^{-324}$ |
| Machine epsilon $2^{1-p}$ | $2^{-23} \approx 1.19 \times 10^{-7}$ | $2^{-52} \approx 2.22 \times 10^{-16}$ |
| Decimal digits $p \log_{10} 2$ | $\approx 7.2$ | $\approx 16.0$ |
:::

:::note{#recap-layout title="Recap" depth="quick"}
Single: 1 | 8 | 23, bias 127, $E = -126 \dots 127$. Double: 1 | 11 | 52, bias 1023,
$E = -1022 \dots 1023$. Normal value $(-1)^s \times 1.f \times 2^{e - \text{bias}}$. The all-zero and
all-ones exponent fields are special.
:::

## Decoding a pattern: hex to value

:::definition{#decode-ieee term="Method: decode a single-precision word" depth="quick"}
1. Write the 8 hex digits as 32 bits.
2. Split **1 | 8 | 23**. The exponent straddles hex digits: the first hex digit holds the sign and
   the top 3 exponent bits, the second holds the next 4, and the top bit of the third hex digit is
   the last exponent bit.
3. Read $e$ as unsigned. If $e = 0$ or $e = 255$, go to the special cases. Otherwise $E = e - 127$.
4. Write the significand $1.f$ (only the leading fraction bits are usually non-zero).
5. Value $= (-1)^s \times 1.f \times 2^{E}$: shift the point $E$ places and read the binary number.
:::

:::trick{#trick-hex-exponent title="Read the scale from the first three hex digits" depth="standard"}
For a positive normal float, the top 9 bits are $0$ followed by $e$, so the first two-and-a-bit hex
digits give the exponent at a glance: `3F8…` is $e = 127$ (scale $2^0$), `400…` is $e = 128$ ($2^1$),
`408…` is $e = 129$ ($2^2$), `410…` is $e = 130$ ($2^3$), `418…` is $e = 131$ ($2^4$). Each step of
`0x00800000` in the word adds 1 to $e$, which **doubles** the value. A leading `C` instead of `4`
(or `B` instead of `3`) is the same magnitude with the sign bit set.

**Why it works:** bit 23 is the lowest exponent bit, and $2^{23} =$ `0x00800000`. **When it fails:**
for denormals and the special fields, and when adding `0x00800000` would carry into $e = 255$
(that gives infinity, not a double).
:::

### Worked examples: decoding

::::example{#ex-dec-one level="easy" title="The simplest word: 0x3F800000" depth="quick"}
Decode `0x3F800000`.

:::step{why="Hex to bits, four bits per digit."}
$\texttt{3F800000} = 0011\,1111\,1000\,0000\,0000\,0000\,0000\,0000$.
:::

:::step{why="Split 1 | 8 | 23: the exponent is bits 30–23."}
$s = 0$, $e = 0111\,1111 = 127$, $f = 000\ldots0$.
:::

:::step{why="Normal field, so subtract the bias and restore the hidden 1."}
$E = 127 - 127 = 0$; value $= 1.0 \times 2^{0} = 1$.
:::

:::answer
`0x3F800000` $= 1.0$. Remember it: every other exponent is measured from `3F8`.
:::
::::

::::example{#ex-dec-pi level="easy" title="A value near π: 0x40490000" depth="standard"}
Decode `0x40490000`.

:::step{why="Expand the hex digits."}
$0100\,0000\,0100\,1001\,0000\ldots = 0\ \ 1000\,0000\ \ 100\,1001\,0000\ldots$
:::

:::step{why="Exponent field 128 means E = 1, a scale of 2."}
$e = 128$, $E = 1$; $f = 1001001$ followed by zeros.
:::

:::step{why="Shift the point of 1.f one place right and read the binary number."}
$1.1001001_2 \times 2^{1} = 11.001001_2 = 3 + \tfrac18 + \tfrac1{64} = 3.140625$.
:::

:::answer
$3.140625 = 201/64$ (close to π, but π itself is not representable).
:::
::::

::::example{#ex-dec-neg level="gate" title="A negative value with a bigger exponent" depth="standard"}
Decode `0xC2F70000`.

:::step{why="C = 1100, so the sign bit is 1 and the exponent starts 100."}
$1100\,0010\,1111\,0111\,0000\ldots = 1\ \ 1000\,0101\ \ 111\,0111\,0000\ldots$
:::

:::step{why="e = 1000 0101 = 133, so E = 133 − 127 = 6."}
$E = 6$, $1.f = 1.1110111_2$.
:::

:::step{why="Move the point 6 places right: the integer part is 1111011, the fraction part .1."}
$1.1110111_2 \times 2^{6} = 1111011.1_2 = 123.5$, and the sign makes it $-123.5$.
:::

:::answer
`0xC2F70000` $= -123.5$.
:::
::::

::::example{#ex-dec-max level="gate" title="Edge case: the largest finite single, 0x7F7FFFFF" depth="standard"}
Decode `0x7F7FFFFF` exactly, and give it as a power of ten.

:::step{why="7F7FFFFF = 0 11111110 111…1: the largest exponent field that is not reserved, and every fraction bit 1."}
$s = 0$, $e = 254$, $E = 127$, $f = 1\ldots1$ (23 ones).
:::

:::step{why="1.11…1 with 23 ones is a geometric sum, one step of 2^-23 short of 2."}
$1.f = 2 - 2^{-23}$.
:::

:::step{why="Multiply by the scale. Writing it as an integer times a power of two is the safest check."}
$(2 - 2^{-23}) \times 2^{127} = (2^{24} - 1) \times 2^{104} \approx 3.4028 \times 10^{38}$.
:::

:::answer
$(2 - 2^{-23})\,2^{127} = (2^{24} - 1)\,2^{104} \approx 3.40 \times 10^{38}$. Not $(2^{24} - 1)\,2^{127}$:
that forgets to scale the 24-bit integer by $2^{-23}$ (a slip in one reference set).
:::
::::

:::note{#recap-decode title="Recap" depth="quick"}
Hex → bits → split 1 | 8 | 23 → check for $e = 0$ or $255$ → $E = e - 127$ → shift the point of
$1.f$ by $E$. Use `3F8` = 1.0 as the landmark: each `0x00800000` doubles.
:::

## Encoding a value: decimal to hex

:::definition{#encode-ieee term="Method: encode a decimal value in single precision" depth="quick"}
1. **Sign:** $s = 1$ for negative.
2. **Binary:** convert $|x|$ to binary (integer part by division, fraction part by doubling).
3. **Normalise** to $1.f \times 2^{E}$.
4. **Exponent field:** $e = E + 127$ in 8 bits.
5. **Fraction field:** the bits after the point, padded with zeros to 23 bits; if the expansion is
   longer (or recurring), **round to nearest, ties to even** (Lesson 7).
6. **Assemble** $s \mid e \mid f$ and regroup into 8 hex digits.
:::

:::viz{#encode-viz spec="ieee-encode" mode="animate" depth="standard"}
:::

:::derivation{#exactness of="which decimals are stored exactly" depth="standard"}
A float is $\pm m \times 2^{E - 23}$ with an integer $m < 2^{24}$. So a value is exactly
representable (in the normal range) iff it equals an integer of at most 24 significant bits times a
power of two. By Lesson 3's terminating theorem, a decimal fraction $a/b$ in lowest terms terminates
in binary only when $b$ is a power of 2. So $0.5, 0.75, 13.625 = 109/8$ are exact, while
$0.1 = 1/10$ recurs ($0.0\overline{0011}_2$) and must be rounded.

**Sanity check.** Integers are exact up to $2^{24} = 16\,777\,216$; the next integer, $2^{24} + 1$,
needs 25 significant bits and is not a float.
:::

### Worked examples: encoding

::::example{#ex-enc-one level="easy" title="Encode 1.0 and −1.0" depth="quick"}
Encode $1.0$ and $-1.0$ in single precision.

:::step{why="1.0 is already normalised: 1.0 × 2^0, with an empty fraction."}
$E = 0$, so $e = 127 = 0111\,1111$ and $f = 0$.
:::

:::step{why="Assemble 0 | 01111111 | 0…0 and regroup in fours."}
$0011\,1111\,1000\,0000\ldots = $ `3F800000`. Setting the sign bit adds 8 to the first hex digit: `BF800000`.
:::

:::answer
$1.0 \to$ `3F800000`, $-1.0 \to$ `BF800000`.
:::
::::

::::example{#ex-enc-12 level="medium" title="Encode 12.5" depth="standard"}
Encode $12.5$ in single precision.

:::step{why="Binary: 12 = 1100 and 0.5 = 0.1."}
$12.5 = 1100.1_2$.
:::

:::step{why="Move the point 3 places left to get 1.f."}
$1100.1 = 1.1001 \times 2^{3}$.
:::

:::step{why="Bias the exponent; copy the bits after the point into the fraction field."}
$e = 3 + 127 = 130 = 1000\,0010$; $f = 1001\,0000\ldots$
:::

:::step{why="Assemble and regroup: the exponent straddles the first three hex digits."}
$0\ 10000010\ 1001000\ldots = 0100\,0001\,0100\,1000\,0000\ldots = $ `41480000`.
:::

:::answer
$12.5 \to$ `0x41480000`.
:::
::::

::::example{#ex-enc-small level="gate" title="Encode a small negative value: −0.09375" depth="standard"}
Encode $-0.09375$ in single precision.

:::step{why="0.09375 = 3/32, so its binary fraction terminates."}
$0.09375 = 0.00011_2$.
:::

:::step{why="The first 1 is 4 places after the point, so E = −4."}
$0.00011 = 1.1 \times 2^{-4}$.
:::

:::step{why="Negative exponents are where the bias earns its keep: 127 − 4 = 123."}
$e = 123 = 0111\,1011$; $f = 1000\ldots$; $s = 1$.
:::

:::step{why="Assemble 1 | 01111011 | 1000… and regroup."}
$1011\,1101\,1100\,0000\ldots = $ `BDC00000`.
:::

:::answer
$-0.09375 \to$ `0xBDC00000`. Check: $-1.5 \times 2^{123 - 127} = -1.5/16 = -0.09375$.
:::
::::

::::example{#ex-enc-tenth level="gate" title="Edge case: 0.1, a recurring fraction" depth="standard"}
Encode $0.1$ in single precision and find the value actually stored.

:::step{why="1/10 recurs in binary (Lesson 3): 0.0 0011 0011 0011 …"}
$0.1 = 0.000110011001100\ldots_2 = 1.100110011001100\ldots_2 \times 2^{-4}$.
:::

:::step{why="E = −4, so e = 123."}
$e = 123 = 0111\,1011$.
:::

:::step{why="Take 23 fraction bits; the next bits decide the rounding."}
Fraction: $1001\,1001\,1001\,1001\,1001\,100\ |\ 11001\ldots$ The bits after the cut start $11$, more
than half an ulp, so **round up**: the fraction ends $\ldots1101$.
:::

:::step{why="Assemble 0 | 01111011 | 10011001100110011001101 and regroup."}
$0011\,1101\,1100\,1100\,1100\,1100\,1100\,1101 = $ `3DCCCCCD`.
:::

:::answer
`0x3DCCCCCD`, which stores $0.100000001490116\ldots$, slightly **above** $0.1$. Truncating instead
would give `3DCCCCCC`, slightly below.
:::
::::

:::trap{#trap-hidden-one title="Storing the hidden 1, or forgetting the bias" depth="quick"}
The two classic encoding slips: copying the leading 1 into the fraction field (it is implicit), and
writing $E$ instead of $E + 127$. For $-14.25 = -1.11001 \times 2^{3}$ the right word is `C1640000`;
storing the 1 gives a fraction starting $111001$ (`C1720000`), and forgetting the bias gives a
completely different exponent. Decode your answer before you mark it.
:::

:::note{#recap-encode title="Recap" depth="quick"}
Sign → binary → $1.f \times 2^E$ → $e = E + 127$ → 23 fraction bits (round to nearest even if they
do not fit) → regroup into hex. Only fractions with a power-of-two denominator are exact.
:::

## Special values: zero, infinity and NaN

:::intuition{#special-intuition title="The two end fields are reserved" depth="standard"}
A hidden-bit format cannot write zero (there is no leading 1), and real programs also need to say
"this overflowed" and "this is not a number at all". IEEE-754 takes the two end exponent fields away
from ordinary numbers. The all-zero field means "no hidden 1": zero and the denormals. The all-ones
field means "not finite": infinity and NaN. Everything in between is an ordinary normal number.
:::

:::definition{#special-values term="How IEEE-754 reads the exponent field" depth="quick"}
| Exponent field $e$ | Fraction $f$ | Meaning | Single-precision value |
|:--|:--|:--|:--|
| $0000\,0000$ | $0$ | zero | $\pm 0$ (sign kept) |
| $0000\,0000$ | $\ne 0$ | denormal (subnormal) | $(-1)^s \times 0.f \times 2^{-126}$ |
| $1 \dots 254$ | any | normal | $(-1)^s \times 1.f \times 2^{e - 127}$ |
| $1111\,1111$ | $0$ | infinity | $\pm\infty$ |
| $1111\,1111$ | $\ne 0$ | NaN | not a number (sign ignored) |

Double precision reads its 11-bit field the same way, with $2^{-1022}$ for denormals and bias 1023.
:::

:::viz{#special-viz spec="ieee-special-values" mode="animate" depth="standard"}
:::

:::definition{#signed-zero term="Signed zero" depth="standard"}
`0x00000000` is $+0$ and `0x80000000` is $-0$. They **compare equal** ($+0 = -0$ is true), but the
sign survives in places where it matters: $1/(+0) = +\infty$ and $1/(-0) = -\infty$. A tiny negative
result that underflows becomes $-0$, so the sign of a value too small to store is not lost. Note
that $0$ is a **special value**, not a normalised number: the exponent field 0 switches the hidden
bit off.
:::

:::definition{#infinity term="Infinity" depth="standard"}
$e$ all ones with $f = 0$: `0x7F800000` $= +\infty$, `0xFF800000` $= -\infty$. Infinity is the result
of overflow (in the default rounding mode) and of dividing a non-zero number by zero. It behaves like
a limit: $\infty + 1 = \infty$, $1/\infty = +0$, $-\infty < x < +\infty$ for every finite $x$.
:::

:::definition{#nan term="NaN (not a number)" depth="standard"}
$e$ all ones with $f \ne 0$. NaN is the result of operations with no sensible value: $0/0$,
$\infty - \infty$, $0 \times \infty$, $\sqrt{-1}$. Any arithmetic with a NaN gives NaN, and **every
comparison involving NaN is false**, even `x == x`; that is how programs test for NaN. Single precision
has $2 \times (2^{23} - 1) = 16\,777\,214$ NaN patterns (two signs, any non-zero fraction); the usual
"quiet NaN" is `0x7FC00000`.
:::

::::example{#ex-sp-zero level="easy" title="Two zeros" depth="quick"}
What do `0x00000000` and `0x80000000` represent, and are they equal?

:::step{why="Both have e = 0 and f = 0, which is the zero row of the table."}
`00000000`: $s = 0$, so $+0$. `80000000`: only the sign bit set, so $-0$.

:::step{why="IEEE defines the two zeros as equal under comparison; only their sign differs."}
$+0 = -0$ compares true.

$+0$ and $-0$; equal when compared, different when you divide by them.

::::

Classify `0x7F800000`, `0xFF800000` and `0x7F7FFFFF`.

:::step{why="7F800000 = 0 11111111 000…0: exponent all ones, fraction zero."}
`7F800000` $= +\infty$; `FF800000` is the same with the sign set, $-\infty$.
:::

:::step{why="7F7FFFFF has e = 254, which is still a normal field."}
`7F7FFFFF` is the largest finite single, $(2 - 2^{-23})\,2^{127}$.

$+\infty$, $-\infty$, and the largest finite value, which is exactly one pattern below $+\infty$.

::::

::::example{#ex-sp-nan level="gate" title="NaN patterns" depth="standard"}
Is `0x7FC00000` a number? How many single-precision patterns are NaN?

:::step{why="7FC00000 = 0 11111111 1000…0: exponent all ones, fraction non-zero."}
It is a NaN (the standard quiet NaN).
:::

:::step{why="A NaN needs e = 255 and any of the 2^23 − 1 non-zero fractions, with either sign."}
Count $= 2 \times (2^{23} - 1) = 16\,777\,214$.
:::

:::answer
Not a number. There are 16 777 214 NaN patterns; together with $\pm\infty$ the field 255 uses
$2^{24}$ patterns.
:::
::::

::::example{#ex-sp-ops level="gate" title="Edge case: results of special operations" depth="standard"}
In single precision, what are $1/(-0)$, $\infty - \infty$, $0 \times \infty$, $(+0) - (+0)$, and the
truth value of `NaN == NaN`?

:::step{why="Dividing a positive number by a signed zero gives an infinity carrying the zero's sign."}
$1/(-0) = -\infty$.
:::

:::step{why="These have no meaningful limit, so IEEE returns NaN."}
$\infty - \infty = \text{NaN}$ and $0 \times \infty = \text{NaN}$.
:::

:::step{why="An exact zero difference is +0 in the default rounding mode."}
$(+0) - (+0) = +0$.
:::

:::step{why="Every comparison with a NaN is false, including equality with itself."}
`NaN == NaN` is false.
:::

:::answer
$-\infty$, NaN, NaN, $+0$, false.
:::
::::

:::note{#recap-special title="Recap" depth="quick"}
$e = 0$: zero ($f = 0$) or denormal. $e = 255$: infinity ($f = 0$) or NaN. Two zeros that compare
equal; NaN is unequal even to itself; 0x00000000 is the *special* value $+0$.
:::

## Denormals and gradual underflow

:::intuition{#denormal-intuition title="The hole around zero" depth="standard"}
With only normal numbers, the smallest positive single is $2^{-126}$, and the next number down is
0. Yet just above $2^{-126}$ the gaps are a tiny $2^{-149}$. So there is a hole between 0 and
$2^{-126}$ that is $2^{23}$ times wider than the gaps next to it. Two different numbers near the
bottom can then have a difference that falls into the hole and becomes 0 (**flush to zero**), which
breaks code like `if (x != y) z = 1/(x - y)`.

**Denormals** (also called subnormals) fill the hole with evenly spaced values, using the spare
patterns with exponent field 0. The precision fades gently as values approach 0 (**gradual
underflow**) instead of falling off a cliff.
:::

:::definition{#denormal term="Denormal (subnormal) numbers" depth="quick"}
A pattern with $e = 0$ and $f \ne 0$ is a **denormal**. It has **no hidden 1**, and its exponent is
fixed at the smallest normal exponent:

$$
x = (-1)^{s} \times 0.f \times 2^{-126} \quad \text{(single)}, \qquad (-1)^{s} \times 0.f \times 2^{-1022} \quad \text{(double)}.
$$

So the denormals are the multiples of $2^{-149}$ from $2^{-149}$ (only the last fraction bit set) to
$(1 - 2^{-23})\,2^{-126}$ (all fraction bits set). The exponent is $1 - \text{bias} = -126$, **not**
$0 - \text{bias} = -127$.
:::

:::derivation{#denormal-why of="why the denormal exponent is −126, not −127" depth="standard"}
Read the field $e = 0$ naively as $E = 0 - 127 = -127$ with no hidden 1: the largest such value would
be $0.11\ldots1 \times 2^{-127} \approx 2^{-127}$, leaving a gap from $2^{-127}$ up to the smallest
normal $2^{-126}$, and the spacing would be $2^{-150}$, half of the spacing just above. Using
$E = -126$ instead:

- the largest denormal is $(1 - 2^{-23})\,2^{-126} = 2^{-126} - 2^{-149}$, exactly one step below the
  smallest normal $2^{-126}$;
- every denormal step is $2^{-23} \times 2^{-126} = 2^{-149}$, the **same** as the step between the
  smallest normals ($1.000\ldots0$ and $1.000\ldots1$ times $2^{-126}$).

So the numbers run 0, $2^{-149}$, $2 \cdot 2^{-149}$, … evenly all the way up to $2^{-125}$ with no
seam. **Sanity check** (bit patterns): `0x007FFFFF` + 1 = `0x00800000`, and the values go from
$2^{-126} - 2^{-149}$ to $2^{-126}$, one step.
:::

:::viz{#underflow-viz spec="gradual-underflow" mode="animate" depth="standard"}
:::

:::theorem{#gradual-underflow name="With denormals, x ≠ y implies x − y ≠ 0" depth="standard"}
In IEEE-754 single precision (with denormals), if $x$ and $y$ are finite floats and $x \ne y$, then the
computed difference $x - y$ is not zero. Without denormals (flush to zero) this fails.
:::

:::proof{#proof-gradual-underflow of="x ≠ y implies x − y ≠ 0" depth="deep"}
**Idea first:** every float is a whole number of the smallest step $2^{-149}$, and every small
multiple of that step is itself a float.

A normal float is $1.f \times 2^{E} = m \times 2^{E - 23}$ with an integer $m$ and $E \ge -126$, so it is
an integer multiple of $2^{-149}$; a denormal is $f \times 2^{-149}$. Hence $x - y = k \times 2^{-149}$
for a non-zero integer $k$.

If $|x - y| < 2^{-126}$, then $|k| < 2^{23}$ and $k \times 2^{-149}$ is exactly a denormal, so the
subtraction is exact and non-zero. If $|x - y| \ge 2^{-126}$, rounding to nearest cannot produce 0,
because $2^{-126}$ is itself a float lying between 0 and the exact result. Either way the result is
non-zero.

**Without denormals:** take $x = 1.25 \times 2^{-126}$ and $y = 2^{-126}$. Both are normal, but
$x - y = 2^{-128}$ is below $2^{-126}$, so a flush-to-zero machine returns 0.
:::

### Worked examples: denormals

::::example{#ex-den-min level="easy" title="The smallest positive float" depth="quick"}
Decode `0x00000001`.

:::step{why="e = 0 and f = 0…01, so it is a denormal: no hidden 1, exponent −126."}
$x = 0.000\ldots01_2 \times 2^{-126} = 2^{-23} \times 2^{-126}$.
:::

:::step{why="Add the exponents; then compare with the smallest normal to see how far below it we are."}
$2^{-23} \times 2^{-126} = 2^{-149}$, which is $2^{23}$ times smaller than the smallest normal $2^{-126}$.
:::

:::answer
$2^{-149} \approx 1.40 \times 10^{-45}$, the smallest positive single.
:::
::::

::::example{#ex-den-half level="medium" title="A denormal with the top fraction bit set" depth="standard"}
Decode `0x00400000`.

:::step{why="00400000 = 0 00000000 1000…0, so e = 0 and f = 100…0: a denormal."}
$0.f = 0.1_2 = \tfrac12$.
:::

:::step{why="Denormals use the fixed exponent −126 and no hidden 1."}
$x = \tfrac12 \times 2^{-126} = 2^{-127}$.
:::

:::answer
$2^{-127} \approx 5.88 \times 10^{-39}$, a value no normal single can hold.
:::
::::

::::example{#ex-den-seam level="gate" title="The largest denormal and the smallest normal" depth="standard"}
Decode `0x007FFFFF` and `0x00800000`, and find the gap between them.

:::step{why="007FFFFF has e = 0 and all 23 fraction bits 1: the largest denormal."}
$(1 - 2^{-23}) \times 2^{-126} = 2^{-126} - 2^{-149}$.
:::

:::step{why="00800000 has e = 1 and f = 0: the smallest normal, 1.0 × 2^(1 − 127)."}
$1.0 \times 2^{-126} = 2^{-126}$.
:::

:::step{why="Subtract: the step across the seam equals the step everywhere below it."}
Gap $= 2^{-149}$.
:::

:::answer
$2^{-126} - 2^{-149}$ and $2^{-126}$, one step of $2^{-149}$ apart: the two patterns are consecutive
integers and the values are consecutive floats.
:::
::::

::::example{#ex-den-diff level="gate" title="Edge case: a difference with and without denormals" depth="standard"}
Let $x = 1.25 \times 2^{-126}$ and $y = 2^{-126}$ (both normal). Compute $x - y$ in IEEE single
precision, and on a machine that flushes results below $2^{-126}$ to zero.

:::step{why="The exact difference is a quarter of the smallest normal."}
$x - y = 0.25 \times 2^{-126} = 2^{-128}$.
:::

:::step{why="2^-128 = 0.01 × 2^-126 is a multiple of 2^-149, so it is exactly a denormal."}
With denormals: the result is the denormal with $f = 0100\ldots0$, i.e. `0x00200000`, exactly $2^{-128}$.
:::

:::step{why="Below the smallest normal, a flush-to-zero machine returns 0."}
Without denormals: $x - y = 0$ although $x \ne y$.
:::

:::answer
IEEE: $2^{-128}$ (`0x00200000`). Flush to zero: $0$, which would make `1/(x - y)` divide by zero.
:::
::::

:::trap{#trap-denormal title="Denormal slips that examiners use" depth="quick"}
Three wrong statements appear in reference material: that the pattern $0\ldots01$ is "the smallest
number $2^{-126}$" (it is the denormal $2^{-149}$; the smallest **normal** is $2^{-126}$), that
denormals use exponent $-127$ (they use $-126$), and that denormals give "larger negative numbers"
(they fill the gap $(0, 2^{-126})$ in magnitude, on both signs, closer to zero).
:::

:::note{#recap-denormal title="Recap" depth="quick"}
$e = 0$, $f \ne 0$: $0.f \times 2^{-126}$, no hidden 1. Denormals are the multiples of $2^{-149}$ below
$2^{-126}$, evenly spaced with the same step as the first normal binade. They guarantee
$x \ne y \Rightarrow x - y \ne 0$.
:::

## The extremes: largest and smallest values

:::derivation{#extremes of="the largest and smallest single-precision values" depth="quick"}
**Largest finite.** The largest normal field is $e = 254$ ($E = 127$) and the largest significand is
$1.11\ldots1 = 2 - 2^{-23}$:

$$
x_{\max} = (2 - 2^{-23})\,2^{127} = (2^{24} - 1)\,2^{104} \approx 3.4028 \times 10^{38} \quad (\texttt{0x7F7FFFFF}).
$$

**Smallest positive normal.** $e = 1$, $f = 0$: $\;2^{-126} \approx 1.1755 \times 10^{-38}$ (`0x00800000`).

**Largest denormal.** $e = 0$, $f$ all ones: $\;(1 - 2^{-23})\,2^{-126}$ (`0x007FFFFF`).

**Smallest positive denormal.** $e = 0$, $f = 0\ldots01$: $\;2^{-149} \approx 1.4013 \times 10^{-45}$ (`0x00000001`).

**Most negative finite.** $-x_{\max}$ (`0xFF7FFFFF`); the format is symmetric about 0.

**Double precision**, by the same reasoning with $f = 52$ and $E_{\max} = 1023$, $E_{\min} = -1022$:
$(2 - 2^{-52})\,2^{1023} \approx 1.7977 \times 10^{308}$, $2^{-1022} \approx 2.2251 \times 10^{-308}$ and
$2^{-1074} \approx 4.94 \times 10^{-324}$.

**Sanity check.** $x_{\max}$ must be below $2^{128}$ (the value of the reserved field $e = 255$ if it
were ordinary) and above $2^{127}$: $3.40 \times 10^{38}$ lies between $2^{127} \approx 1.70 \times 10^{38}$
and $2^{128} \approx 3.40 \times 10^{38}$, just under the top.
:::

:::trap{#trap-largest title="Three wrong versions of the largest float" depth="quick"}
- $(2^{24} - 1) \times 2^{127}$: the 24-bit significand was not scaled by $2^{-23}$; this is $\approx 2.9 \times 10^{45}$, larger than $+\infty$'s threshold.
- Exponent field $1111\,1111$: that field is infinity and NaN; the largest finite uses $1111\,1110$ (one set of notes even prints a 7-bit $1111110$).
- $2^{128}$: not representable; it is where overflow to $+\infty$ begins.
:::

### Worked examples: extremes

::::example{#ex-ext-hex level="easy" title="The largest finite single in hex" depth="quick"}
Write the largest finite single-precision value and the most negative finite value in hex.

:::step{why="Largest: sign 0, exponent 1111 1110, fraction all ones."}
$0\ 11111110\ 1\ldots1 = 0111\,1111\,0111\,1111\ldots1111 = $ `7F7FFFFF`.
:::

:::step{why="The most negative finite value is the same magnitude with the sign bit set."}
`FF7FFFFF`.
:::

:::answer
`7F7FFFFF` $\approx 3.40 \times 10^{38}$ and `FF7FFFFF` $\approx -3.40 \times 10^{38}$.
:::
::::

::::example{#ex-ext-double level="medium" title="The smallest normal double" depth="standard"}
Write the smallest positive normal double in hex, and give its value.

:::step{why="Double: 1 | 11 | 52. The smallest normal has e = 1 and f = 0."}
$0\ 00000000001\ 0\ldots0$.
:::

:::step{why="Regroup the 64 bits: the first three hex digits hold the sign and the 11-bit exponent."}
$0000\,0000\,0001\,0000\ldots = $ `0010000000000000`.
:::

:::answer
`0x0010000000000000` $= 2^{1 - 1023} = 2^{-1022} \approx 2.23 \times 10^{-308}$.
:::
::::

::::example{#ex-ext-ratio level="gate" title="How much larger is the largest double?" depth="standard"}
Find the ratio of the largest finite double to the largest finite single, as a power of 2 and of 10.

:::step{why="Write both maxima in the (2 − ulp) × 2^Emax form."}
$\dfrac{(2 - 2^{-52})\,2^{1023}}{(2 - 2^{-23})\,2^{127}}$.
:::

:::step{why="The significand factors are both within a millionth of 2, so their ratio is essentially 1."}
Ratio $\approx 2^{1023 - 127} = 2^{896}$.
:::

:::step{why="Convert with log10 2 ≈ 0.30103."}
$896 \times 0.30103 \approx 269.7$, so the ratio is about $10^{270}$.
:::

:::answer
About $2^{896} \approx 10^{270}$.
:::
::::

::::example{#ex-ext-next level="gate" title="Edge case: one more than the largest pattern" depth="standard"}
Add 1 to the integer `0x7F7FFFFF`. What pattern do you get, and what does it mean?

:::step{why="Adding 1 to a fraction of all ones carries into the exponent field."}
$\texttt{7F7FFFFF} + 1 = \texttt{7F800000}$: fraction 0, exponent $1111\,1111$.
:::

:::step{why="Exponent all ones with fraction 0 is the infinity row."}
`7F800000` $= +\infty$.
:::

:::answer
$+\infty$. Consecutive patterns are consecutive floats all the way up, and the float after the
largest finite value is infinity itself.
:::
::::

:::note{#recap-extremes title="Recap" depth="quick"}
Largest $(2 - 2^{-23})2^{127} \approx 3.4 \times 10^{38}$ (`7F7FFFFF`); smallest normal $2^{-126}$
(`00800000`); smallest denormal $2^{-149}$ (`00000001`). Double: $\approx 1.8 \times 10^{308}$,
$2^{-1022}$, $2^{-1074}$.
:::

## Precision: machine epsilon, ulp and decimal digits

:::definition{#machine-epsilon term="Machine epsilon and unit roundoff" depth="quick"}
**Machine epsilon** $\varepsilon$ is the gap between $1$ and the next larger float:

$$
\varepsilon = 2^{1 - p} = 2^{-23} \approx 1.19 \times 10^{-7} \ \text{(single)}, \qquad 2^{-52} \approx 2.22 \times 10^{-16} \ \text{(double)} .
$$

The **unit roundoff** $u = \varepsilon / 2 = 2^{-p}$ ($2^{-24}$, $2^{-53}$) bounds the relative error of
rounding to nearest: for any $x$ in the normal range, $|\text{fl}(x) - x| \le u\,|x|$. Some books call
$u$ "machine epsilon", so check which one a question means.
:::

:::derivation{#ulp-ieee of="the ulp of a single-precision value" depth="standard"}
A normal value $x$ with $2^{E} \le |x| < 2^{E+1}$ has neighbours $2^{E - 23}$ apart (Lesson 5's
ulp with $f = 23$):

$$
\text{ulp}(x) = 2^{E - 23}, \qquad \text{ulp}(x) = 2^{-149} \text{ for denormals.}
$$

Rounding to nearest errs by at most half an ulp, $2^{E - 24}$, and since $|x| \ge 2^{E}$ the
relative error is at most $2^{-24} = u$.

**Decimal digits.** $p = 24$ bits are worth $24 \log_{10} 2 \approx 7.2$ decimal digits, $p = 53$ bits
about $16.0$. So a float keeps "about 7 significant digits" and a double "about 16".

**Sanity check.** $\text{ulp}(1) = 2^{0 - 23} = \varepsilon$, as it should be.
:::

### Worked examples: precision

::::example{#ex-prec-eps level="easy" title="The float after 1.0" depth="quick"}
What is the next single-precision value after $1.0$, in hex and in decimal?

:::step{why="1.0 is 3F800000; the next float is the next pattern."}
`3F800001`: the same exponent, fraction $0\ldots01$.
:::

:::step{why="The last fraction bit is worth 2^-23 at exponent 0."}
Value $1 + 2^{-23} \approx 1.00000012$.
:::

:::answer
`0x3F800001` $= 1 + 2^{-23}$; the gap $2^{-23} \approx 1.19 \times 10^{-7}$ is machine epsilon.
:::
::::

::::example{#ex-prec-1000 level="medium" title="The ulp of 1000" depth="standard"}
How far apart are the single-precision values near $1000$?

:::step{why="Find the binade: 512 ≤ 1000 < 1024."}
$2^{9} \le 1000 < 2^{10}$, so $E = 9$.
:::

:::step{why="ulp = 2^(E − 23)."}
$\text{ulp} = 2^{9 - 23} = 2^{-14} = 0.00006103515625$.
:::

:::answer
About $6.1 \times 10^{-5}$: a float near 1000 can resolve steps of about 0.00006, i.e. 7 significant digits.
:::
::::

::::example{#ex-prec-int level="gate" title="The smallest positive integer that is not a float" depth="standard"}
Find the smallest positive integer that single precision cannot store exactly.

:::step{why="An integer is exact when it has at most 24 significant bits."}
Every integer up to $2^{24} = 16\,777\,216$ is exact ($2^{24}$ itself is $1.0 \times 2^{24}$).
:::

:::step{why="Above 2^24 the ulp is 2^(24 − 23) = 2, so only even integers survive."}
$2^{24} + 1 = 16\,777\,217$ falls exactly halfway between $2^{24}$ and $2^{24} + 2$; it rounds (to even)
to $2^{24}$.
:::

:::answer
$16\,777\,217 = 2^{24} + 1$. (For double it is $2^{53} + 1$.)
:::
::::

::::example{#ex-prec-sum level="gate" title="Edge case: 0.1 + 0.2 in double precision" depth="standard"}
Why does $0.1 + 0.2 == 0.3$ evaluate to false in double precision?

:::step{why="None of 0.1, 0.2, 0.3 is exact in binary; each is rounded to 53 bits on input."}
Stored: $0.1 \to 0.1000000000000000055\ldots$, $0.2 \to 0.2000000000000000111\ldots$,
$0.3 \to 0.2999999999999999888\ldots$
:::

:::step{why="The sum of the two stored values is rounded again, to the nearest double."}
$\text{fl}(0.1 + 0.2) = 0.3000000000000000444\ldots$ (pattern `3FD3333333333334`).
:::

:::step{why="The stored 0.3 is the neighbouring double, one ulp (2^-54 ≈ 5.6 × 10^-17) below."}
`3FD3333333333333` $\ne$ `3FD3333333333334`.
:::

:::answer
The two sides differ by one ulp. Compare floats with a tolerance ($|a - b| \le$ a few ulps), never with `==`.
:::
::::

:::note{#recap-precision title="Recap" depth="quick"}
$\varepsilon = 2^{-23}$ (single), $2^{-52}$ (double); unit roundoff $u = \varepsilon/2$. ulp$(x) = 2^{E-23}$.
About 7 and 16 decimal digits. Integers are exact up to $2^{24}$ (single) and $2^{53}$ (double).
:::

## Comparing floats by their bit patterns

:::theorem{#compare-bits name="Non-negative floats compare like unsigned integers" depth="standard"}
For non-negative single-precision values that are not NaN (zero, denormals, normals and $+\infty$),
$x < y$ exactly when the bit pattern of $x$ is smaller than the bit pattern of $y$ read as an
unsigned integer. For negative values the order is reversed: a larger pattern (with the sign bit
set) is a more negative number.
:::

:::proof{#proof-compare-bits of="ordering floats by their patterns" depth="deep"}
**Idea first:** the exponent field sits above the fraction field and is biased, so the bits are in
order of significance, exactly as in Lesson 5's theorem.

For sign 0, the pattern is $e \cdot 2^{23} + f$. If $e_x < e_y$: the value of $x$ is below $2^{e_x - 126}$
(or below $2^{-126}$ for a denormal) and the value of $y$ is at least $2^{e_y - 127} \ge 2^{e_x - 126}$, so
$x < y$, and the pattern of $x$ is smaller because its exponent field is. If $e_x = e_y$, both values
are $(\text{hidden bit} + f \cdot 2^{-23})$ times the same power of two, so the larger $f$ is the larger
value. $+\infty$ has the largest exponent field, above every finite value.

For negative numbers the stored magnitude follows the same rule, but a bigger magnitude is a smaller
number, so the order reverses. That is why sorting floats with integer instructions needs a fix-up
for negative values (flip all their bits) and fails for NaN, which is unordered.
:::

### Worked examples: comparing

::::example{#ex-cmp-pos level="easy" title="Two positive patterns" depth="quick"}
Which is larger: `0x41200000` or `0x40F00000`?

:::step{why="Both have sign 0, so compare the patterns as unsigned integers."}
$\texttt{41200000} > \texttt{40F00000}$.
:::

:::step{why="Decode to confirm: 41200000 is 1.25 × 2^3; 40F00000 is 1.875 × 2^2."}
$10 > 7.5$. ✓
:::

:::answer
`0x41200000` $= 10$ is larger.
:::
::::

::::example{#ex-cmp-neg level="medium" title="Two negative patterns" depth="standard"}
Which is larger: `0xC1200000` or `0xC0F00000`?

:::step{why="Both have the sign bit set; the larger pattern has the larger magnitude."}
$\texttt{C1200000}$ has magnitude 10, $\texttt{C0F00000}$ has magnitude 7.5.
:::

:::step{why="For negative numbers, a larger magnitude means a smaller value."}
$-10 < -7.5$.
:::

:::answer
`0xC0F00000` $= -7.5$ is larger, although its pattern is smaller.
:::
::::

::::example{#ex-cmp-pick level="gate" title="Pick the largest of four patterns" depth="standard"}
Which is the largest number: (A) `3FFFFFFF`, (B) `7F000000`, (C) `7FC00001`, (D) `00FFFFFF`?

:::step{why="Classify first: an exponent field of all ones is not a number to compare."}
(C) = 0 11111111 1000…01: exponent 255 with a non-zero fraction, so NaN. It is not a candidate.
:::

:::step{why="The remaining patterns are positive, so the largest unsigned pattern is the largest value."}
$\texttt{7F000000} > \texttt{3FFFFFFF} > \texttt{00FFFFFF}$.
:::

:::step{why="Decode to confirm the scales."}
(B) $= 1.0 \times 2^{254 - 127} = 2^{127}$; (A) $\approx 2 - 2^{-23} \approx 2$; (D) $\approx 2^{-125}$.
:::

:::answer
(B), $2^{127}$. The pattern (C) is "bigger" as an integer but is NaN.
:::
::::

::::example{#ex-cmp-edge level="gate" title="Edge case: ±0 and NaN under integer comparison" depth="standard"}
Compare `0x00000000` with `0x80000000`, and a NaN with itself, both as floats and as integers.

:::step{why="As floats, the two zeros are equal."}
$+0 = -0$ is true; as unsigned integers $0 < 2^{31}$, so integer comparison calls them different.
:::

:::step{why="As floats, NaN is unordered: every comparison is false."}
`NaN == NaN` is false, while integer comparison calls the same pattern equal to itself.
:::

:::answer
Bit-pattern comparison is right for ordinary non-negative values, but it disagrees with IEEE rules on
$\pm 0$ and on NaN; real hardware compares floats with dedicated rules for these cases.
:::
::::

:::note{#recap-compare title="Recap" depth="quick"}
Non-negative floats (not NaN) sort like unsigned integers; negatives sort in reverse. The next float
is the next pattern. Watch for $\pm 0$ (equal as floats) and NaN (unordered).
:::

## Double precision in one go

Double precision changes only the widths: 11 exponent bits with bias 1023 and 52 fraction bits.
Every method above carries over; hex words are 16 digits, and the first three hex digits hold the
sign and the exponent.

### Worked examples: double precision

::::example{#ex-dbl-one level="easy" title="1.0 and −2.5 as doubles" depth="quick"}
Encode $1.0$ and $-2.5$ in double precision.

:::step{why="1.0 has E = 0, so e = 1023 = 011 1111 1111."}
$0\ 01111111111\ 0\ldots0 = $ `3FF0000000000000`.
:::

:::step{why="−2.5 = −10.1₂ = −1.01 × 2^1, so e = 1024 = 100 0000 0000 and f = 0100…"}
$1\ 10000000000\ 0100\ldots = 1100\,0000\,0000\,0100\,0000\ldots = $ `C004000000000000`.
:::

:::answer
`3FF0000000000000` and `C004000000000000`.
:::
::::

::::example{#ex-dbl-tenth level="medium" title="0.1 as a double" depth="standard"}
Encode $0.1$ in double precision.

:::step{why="0.1 = 1.1001 1001 … × 2^-4, so e = 1023 − 4 = 1019 = 011 1111 1011."}
Sign and exponent: $0\ 01111111011$, i.e. the hex digits `3FB`.
:::

:::step{why="The fraction is the repeating 1001 pattern: hex 9999…; the bits after the 52nd start 1001 1…, more than half an ulp, so round up the last digit."}
Fraction $= 999999999999A_{16}$.
:::

:::answer
`0x3FB999999999999A`, slightly above 0.1 (the single-precision version ended in `D` for the same reason).
:::
::::

::::example{#ex-dbl-widen level="gate" title="Widening a single to a double" depth="standard"}
The single `0xC1640000` is converted to double. Write the double's hex pattern.

:::step{why="Decode the single: 1 10000010 1100100… is −1.11001 × 2^3 = −14.25."}
$s = 1$, $E = 130 - 127 = 3$, $f = 11001\,0\ldots$
:::

:::step{why="Re-bias the exponent: the same E with the double's bias, 3 + 1023 = 1026 = 100 0000 0010 (that is, e + 896)."}
$e_{\text{double}} = 1026$.
:::

:::step{why="The fraction is copied and padded with 29 more zeros; the value does not change."}
$1\ 10000000010\ 11001\,0\ldots = 1100\,0000\,0010\,1100\,1000\ldots = $ `C02C800000000000`.
:::

:::answer
`0xC02C800000000000` $= -14.25$. Widening is always exact; narrowing a double to a single may round.
:::
::::

::::example{#ex-dbl-max level="gate" title="Edge case: the largest double, and why it is not 2^1024" depth="standard"}
Write the largest finite double in hex and give its value.

:::step{why="The largest normal exponent field is 111 1111 1110 = 2046 (2047 is reserved)."}
$E = 2046 - 1023 = 1023$.
:::

:::step{why="All 52 fraction bits 1: the significand is 2 − 2^-52."}
$x_{\max} = (2 - 2^{-52})\,2^{1023} \approx 1.7977 \times 10^{308}$.
:::

:::answer
`0x7FEFFFFFFFFFFFFF` $\approx 1.80 \times 10^{308}$; `0x7FF0000000000000` is $+\infty$.
:::
::::

:::aside{#bias-history title="Which bias does a GATE question use?" depth="standard"}
Every IEEE question since 2008 uses bias 127 (single) or 1023 (double); GATE 2021 even states "with a
bias of 127". Older papers set their own formats with other exponent codes (excess-64, 2's
complement, sign-magnitude, bias 31): see [Lesson 5's table](lesson:floating-point-basics#bias-conventions).
Some solution sets write the IEEE bias as $2^{k-1} = 128$; that is the excess-$2^{k-1}$ convention of
custom formats, and it is wrong for IEEE.
:::

## Summary

:::summary{#summary-card title="IEEE-754 on one card" depth="quick"}
| Idea | Formula or rule |
|:--|:--|
| Single / double layout | 1 \| 8 \| 23, bias 127 / 1 \| 11 \| 52, bias 1023 |
| Normal value | $(-1)^s \times 1.f \times 2^{e - \text{bias}}$, $1 \le e \le 254$ (single) |
| Denormal | $e = 0$, $f \ne 0$: $(-1)^s \times 0.f \times 2^{-126}$ (no hidden 1) |
| Zero | $e = 0$, $f = 0$: $\pm 0$, equal under comparison |
| Infinity / NaN | $e = 255$: $f = 0 \to \pm\infty$, $f \ne 0 \to$ NaN |
| Landmarks | `3F800000` $= 1$; `+0x00800000` doubles a normal value |
| Largest finite | $(2 - 2^{-23})2^{127} = (2^{24} - 1)2^{104} \approx 3.4 \times 10^{38}$ (`7F7FFFFF`) |
| Smallest normal / denormal | $2^{-126}$ (`00800000`) / $2^{-149}$ (`00000001`) |
| Machine epsilon | $2^{-23}$ (single), $2^{-52}$ (double); $u = \varepsilon/2$ |
| ulp | $2^{E - 23}$ for $2^E \le |x| < 2^{E+1}$; $2^{-149}$ for denormals |
| Exact integers | up to $2^{24}$ (single), $2^{53}$ (double) |
| Comparison | non-negative floats sort like unsigned integers; negatives reverse |
:::

:::note{#further-depth title="Further depth: other IEEE formats" depth="deep"}
IEEE-754-2019 also defines binary16 (1 | 5 | 10, bias 15, largest 65504), widely used in graphics and
machine learning, and binary128 (1 | 15 | 112). Machine-learning hardware adds bfloat16 (1 | 8 | 7),
which keeps single precision's exponent range with only 8 significant bits. Every one of them follows
this lesson's rules: biased exponent, hidden bit, reserved end fields, denormals.
:::
