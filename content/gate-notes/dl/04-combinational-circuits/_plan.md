concept (intuition → definition → why → how → what goes wrong), at least 4 step-format worked
examples per concept (easy → medium → GATE → edge case; the edge case uses `level="gate"` and a
title starting "Edge case:"), a `:::derivation` or `:::theorem` + `:::proof` for every rule GATE
uses, a recap note at the end of each section, animation wherever motion teaches, and every block
carrying an `#id` and a `depth`. Lessons are written to Chapter 3 depth (5–9k words each).

  (lesson 6).

  is [Chapter 1, Lesson 9](lesson:code-arithmetic). Lessons link there instead of re-teaching it.

  parity trees; ROM / PLA / PAL sizing with an exhaustive shared-term search; minimum AND/OR/NOT
  gate search; fault counting, test sets and the Boolean difference) built on Chapter 2's
  `boollib.py` and Chapter 3's `minlib.py`. One module per lesson, `l4_01_design.py` …
  `l4_06_faults.py`: every worked value, viz caption number, PYQ key, practice answer and MSQ

## Lesson 1 · `dl-04-01-combinational-design` · Designing combinational circuits; code converters

**Prerequisites:** dl-03-02 (don't-cares), dl-01-08 (codes). **Covered by sets:** A 38–39, 44–47;
B 117–118; C 201–202, 277–283.

### Teaching sequence
1. **Radar** `#radar`; intuition `#what-combinational` (a combinational circuit is a vending
   machine with no coin memory: the output depends only on what is pressed now).
2. **Definition** `#comb-def` (acyclic gate network; outputs are functions of the present inputs;
   propagation delay); theorem `#acyclic-function` (an acyclic network computes a Boolean function
   of its inputs) + proof (topological order, induction); `:::trap` `#trap-feedback` (a loop of
   gates can hold state: that is a latch, Chapter 6).
3. **The design procedure** `#design-procedure` (spec → name inputs/outputs and bit order → truth
   table → don't-cares → K-map per output → expression → gates → verify); animated
   `design-pipeline`; `:::trap` `#trap-bit-order` (which label is the LSB; 2000 numbers I₁ as the
   LSB).
4. **Truth tables from words** `#truth-table-spec`; matching a table to an expression
   `#match-table` (check rows, not shapes; 2012).
5. **Detectors and voting circuits** `#detectors` (BCD ≥ 5, majority, minority, "at least k of n");
   `:::derivation` `#digit-ge5` ($A + B(C + D)$ with rows 10–15 free); unused codes as don't-cares
   `#dc-illegal` + `:::trap` `#trap-dc-illegal` ("do not detect illegal input" = don't-cares;
   detecting them costs gates).
6. **Counting gates** `#gate-count` (which gates are allowed, fan-in, whether complements are free;
   AND/OR/NOT counts include inverters); theorem `#gate-lower-bound` (a function that is not a
   single literal needs ≥ 1 gate; one gate computes only AND/OR of inputs or a NOT; so a 3-gate
   circuit is minimal once 1 and 2 gates are ruled out) + proof.
7. **Code converters** `#code-converters` (one function per output bit, sharing terms);
   BCD → mod-n `#bcd-mod-n` (2000; residues repeat with period n); BCD → excess-3 `#bcd-to-xs3`
   (E₃ = B₃ + B₂(B₁ + B₀), E₂ = B₂ ⊕ (B₁ + B₀), E₁ = (B₁ ⊕ B₀)′, E₀ = B₀′) with `:::derivation`;
   animated `converter-kmaps`; excess-3 → BCD `#xs3-to-bcd` (2001; minimal POS of b₄, three ties);
   binary ↔ Gray `#binary-gray` (theorem: Gᵢ = Bᵢ ⊕ Bᵢ₊₁ and Bᵢ = Gᵢ ⊕ Bᵢ₊₁ + proof); animated
   `gray-converter`; `:::trap` `#trap-gray-dc` (a converter simplified with rows 10–15 as
   don't-cares is BCD-only; erratum A 38).
8. **Seven-segment decoder** `#seven-segment` (aside, deep: one output per segment, 10 care rows).
9. **Several outputs** `#shared-terms` (link to Chapter 3, Lesson 4's multi-output sharing).
10. **Live Lab** `#lab-design` (Combinational Workbench, implement tab). GATE questions, practice,
    summary `#summary-card`.

### Derivations and proofs
- `:::theorem` acyclic networks compute functions + proof; `:::theorem` the gate lower bound +
  proof; `:::derivation` digit ≥ 5; `:::derivation` BCD → excess-3 (four maps); `:::theorem`
  binary ↔ Gray + proof; `:::derivation` BCD mod 6.

### Worked examples (4 per concept)
- **Design procedure and detectors:** 3-input majority (easy); BCD ≥ 5 with AND/OR/NOT counted
  (medium, the 2004 pattern); "at least two of four switches" (GATE); edge case: the same
  detector when illegal codes must output 0 (the don't-cares disappear and the cost rises).
- **Truth tables and matching:** read f(X, Y) from a 4-row table (easy, the 2012 pattern);
  a table with don't-care inputs (medium); which of four expressions equal a table (GATE);
  edge case: a table whose rows are not in counting order.
- **Code converters:** BCD → excess-3 bit E₀ and E₁ (easy); BCD mod 5 (medium); excess-3 → BCD
  b₈ as a minimal POS (GATE); edge case: binary → Gray with and without the BCD don't-cares.

### Tricks and traps
- `:::trick` `#trick-period` (mod-n of BCD: the low bit passes through when n is even);
  `#trick-xor-converter` (Gray bit = XOR of neighbours).
- `:::trap` `#trap-feedback`, `#trap-bit-order`, `#trap-dc-illegal`, `#trap-gray-dc`.

### Diagrams and animations
- `design-pipeline` (animate): a word spec ("BCD digit ≥ 5") becomes a truth table, a K-map with
  don't-cares, the expression $A + B(C + D)$ and a 3-gate circuit, one stage per step.
- `converter-kmaps` (animate): the four BCD → excess-3 maps, the Xs on rows 10–15, one output's

## Lesson 2 · `dl-04-02-multiplexers` · Multiplexers and function realisation

**Prerequisites:** dl-04-01, dl-02-02 (Shannon). **Covered by sets:** A 64–72; B 119–122;
C 296–325; E 407–408.

### Teaching sequence
1. **Radar** `#radar`; intuition `#mux-intuition` (a railway junction: the lever setting picks
   which track reaches the station).
2. **Definition** `#mux-def` (2ⁿ:1, n select lines, MSB = S_{n−1}); theorem `#mux-equation`
   ($Y = \sum_i m_i(S)\,I_i$) + proof; animated `mux-routing`; select-line sizing `#select-lines`
   (⌈log₂ N⌉; 1998, the 2020 register file); `:::trap` `#trap-select-count` (4 select lines is
   16:1, not 4:1).
3. **Enable** `#mux-enable` (output forced to 0 when disabled; active-low EN); `:::trap`
   `#trap-enable` (a gated row contributes 0, not "don't care"; 2002).
4. **Reading MUX circuits** `#mux-analysis` (write each data input as a function, then
   $Y = \sum m_i I_i$; or case-split on the selects); `:::trick` `#trick-case-split`.
   Cascades `#mux-cascade` (a MUX output driving data or select of another; 2001, 2006, 2016,
   2024, IT 2005, IT 2007); animated `mux-cascade`.
5. **MUX = if–then–else** `#mux-if-else` (2014-3).
6. **Implementing functions** `#mux-implement`: n selects (the truth-table column on the data
   lines) `#impl-n-select`; n − 1 selects and the implementation table `#impl-table` (residues 0,
   1, x, x′); theorem `#shannon-mux` (any n-variable function on a 2^{n−1}:1 MUX with one
   inverter) + proof; minimum size `#min-mux-size` (2007); choosing the residue variable
   `#residue-choice`; fewer selects with function residues `#impl-fewer` (IT 2006 majority);
   animated `mux-implement`; `:::trap` `#trap-select-order` (swapping S₁ and S₀ permutes the data
   inputs; 2023); `:::trap` `#trap-residue-complement` (x′ on a data line needs the inverter).
7. **MUX trees** `#mux-tree` (N:1 from k:1); `:::derivation` `#mux-tree-count` (blocks per level
   ⌈N/k⌉, ⌈N/k²⌉, …; (N − 1)/(k − 1) when N is a power of k; levels ⌈log_k N⌉); animated
   `mux-tree`; `:::trap` `#trap-tree-count` (round up at each level; erratum C 308).
8. **MUX as a universal element** `#mux-universal` (NOT, AND, OR, NAND, NOR from 2:1 MUXes with
   constants); theorem `#mux-complete-proof` + proof (link to Chapter 2's `mux-complete`);
   animated `mux-as-gates`; `:::trap` `#trap-mux-nand` (erratum D 400: a constant cascade gives
   NAND, not OR).
9. **Applications** `#mux-applications` (register selection, function selection, data routing,
   parallel → serial).
10. **Live Lab** `#lab-mux` (mux tab) and `#lab-implement` (implement tab).

### Derivations and proofs
- `:::theorem` MUX equation + proof; `:::theorem` Shannon realisation on a 2^{n−1}:1 MUX + proof;
  `:::derivation` select lines; `:::derivation` MUX-tree counts; `:::theorem` 2:1 MUX with 0 and 1
  is complete + proof.

### Worked examples (4 per concept)
- **Reading MUX circuits:** a 4:1 with data C, C′, C′, C (easy, XOR₃); the 2014 MUX (0, 1, R, R′)
  to a minimal SOP (medium); a two-level cascade (GATE, 2016 pattern); edge case: an enabled MUX
  whose select and enable share a variable (2002 pattern).
- **Implementing with n − 1 selects:** majority on a 4:1 (easy); Σ(0, 1, 3, 4, 5, 6) with selects
  y, z (medium, the 2021 pattern); a 4-variable function on an 8:1 (GATE); edge case: the same
  function with a different residue variable (the table changes, the function does not).
- **Trees and sizing:** select lines for 32 registers (easy); 16:1 from 4:1s (medium); 64:1 from
  4:1 and from 2:1 (GATE); edge case: 10:1 from 4:1s (rounding up).
- **MUX as gates:** NOT and AND from 2:1 MUXes (easy); OR (medium, 2004); NOR from two MUXes
  (GATE, IT 2005); edge case: a constant cascade that is NAND, not OR.

### Tricks and traps
- `:::trick` `#trick-case-split`, `#trick-residue-read` (read a residue column: same → constant,
  equal to the variable → x, opposite → x′).
- `:::trap` `#trap-select-count`, `#trap-enable`, `#trap-select-order`, `#trap-residue-complement`,
  `#trap-tree-count`, `#trap-mux-nand`.

## Lesson 3 · `dl-04-03-decoders-encoders` · Decoders, demultiplexers, encoders and priority encoders

**Prerequisites:** dl-04-02. **Covered by sets:** A 72–75; B 122–129; C 295, 299–325; E 408.

### Teaching sequence
1. **Radar** `#radar`; intuition `#decoder-intuition` (a hotel key panel: one room number in, one
   light on).
2. **Decoder** `#decoder-def` (n:2ⁿ, outputs one-hot, enable; active-high vs active-low);
   theorem `#decoder-minterms` ($D_i = E \cdot m_i$) + proof; animated `decoder-lighting`;
   `#active-low` + `:::trap` `#trap-active-low` (active-low outputs are maxterms: AND/NAND them,
   not OR; erratum C 313).
3. **Functions from a decoder** `#decoder-function` (OR the outputs of f's minterms; or NOR the
   outputs of its 0s; choose the shorter list); theorem `#decoder-or` (decoder + OR realises any
   function; NOR of the other outputs gives the same f) + proof; animated `decoder-function`;
   `:::trap` `#trap-decoder-order` (which address input is the MSB; IT 2008).
4. **Expansion** `#decoder-expansion` (enables; 4:16 from 2:4; 6:64 from 3:8);
   `:::derivation` `#decoder-tree-count` (2^{n−k} leaves + the levels above); animated
   `decoder-tree`; `:::trap` `#trap-decoder-count` (8 is not enough without gates: one more
   decoder drives the enables).
5. **Demultiplexer** `#demux-def` (1:2ⁿ; data on the enable); theorem `#demux-decoder` + proof;
   animated `demux-routing`.
6. **Encoders** `#encoder-def` (2ⁿ:n, OR gates, assumes one active input); priority encoder
   `#priority-encoder` (highest active input wins; valid bit V; table with x's);
   `:::derivation` `#priority-equations` (4:2: X₁ = D₂ + D₃, X₀ = D₃ + D₁D₂′, V = D₀ + D₁ + D₂ + D₃);
   animated `priority-scan`; `:::trap` `#trap-encoder-vs-decoder` (2013's table is an encoder
   because the inputs carry x's and the outputs are codes); a priority encoder from MUXes
   `#priority-mux` (1992).
7. **Address decoding** `#address-decoding` (byte-addressable memory, chip select, 1 KB → 10:1024;
   m + n; 2022's display system); `:::trap` `#trap-address-bits` (words vs bytes; 1 K = 1024).
8. **Decoder and MUX together** `#decoder-mux-combo` (2026: a decoder's outputs on a MUX's data
   lines; count the rows).
9. **Live Lab** `#lab-decoder` (decoder tab).

### Derivations and proofs
- `:::theorem` decoder outputs are minterms + proof; `:::theorem` decoder + OR realises any f
  (and the NOR form) + proof; `:::derivation` decoder-tree count; `:::theorem` DEMUX = decoder with
  data on the enable + proof; `:::derivation` priority-encoder equations.

### Worked examples (4 per concept)
- **Decoder + gate functions:** full-adder sum and carry from a 3:8 decoder (easy); a NOR of four
  outputs (medium, the IT 2008 pattern); an active-low decoder with a NAND (GATE); edge case: the
  same wiring with the address inputs in the opposite order.
- **Expansion:** 3:8 from 2:4 (easy); 4:16 from 2:4 (medium); 6:64 from 3:8 (GATE, 2007);
  edge case: 5:32 from 3:8 (a partly used top decoder).
- **Encoders and priority encoders:** 4:2 encoder with one-hot input (easy); 4:2 priority encoder
  table and equations (medium); identify a block from its table (GATE, 2013); edge case: a
  priority encoder whose lowest index has the highest priority.
- **Address decoding and combos:** decoder for a 1 KB byte-addressable RAM (easy, 2020); a 4 KB
  memory of 1 KB chips (medium); identify P, Q and T (GATE, 2022); edge case: the 2026
  decoder-into-MUX row count.

### Tricks and traps
- `:::trick` `#trick-short-list` (OR the 1s or NOR the 0s, whichever list is shorter);
  `#trick-tree-count` (leaves first, then divide by 2^k until one block).
- `:::trap` `#trap-active-low`, `#trap-decoder-order`, `#trap-decoder-count`,
  `#trap-encoder-vs-decoder`, `#trap-address-bits`.

## Lesson 4 · `dl-04-04-comparators-parity` · Magnitude comparators and parity circuits

**Prerequisites:** dl-04-01, dl-02-03 (XOR). **Covered by sets:** A 61–63; B 132–133; C 279–280,

### Teaching sequence

## Lesson 5 · `dl-04-05-rom-pla-pal` · ROM, PLA and PAL as combinational logic

**Prerequisites:** dl-04-03. **Covered by sets:** B 125, 127–128; C 373–391.

### Teaching sequence
1. **Radar** `#radar`; intuition `#rom-intuition` (a ROM is a printed truth table: look up the row,
   read the answer).

   OR plane); theorem `#rom-any-function` (a 2ⁿ × m ROM implements every n-input, m-output

3. **Sizing** `#rom-sizing` (words = 2^{inputs}, width = outputs, total bits; K = 1024);
   multiplier ROMs `#multiplier-rom` (n × n bits → 2^{2n} words × 2n bits); theorem
   `#product-width` (the product of two n-bit numbers needs exactly 2n bits) + proof; other
   tables (adder: 2n + 1 inputs → n + 1 outputs; squarer; code converter) `#rom-tables`;
   `:::trap` `#trap-rom-width` (2n + 1 or n output bits); `:::trap` `#trap-bits-vs-words` (answer in

## Lesson 6 · `dl-04-06-faults-testing` · Stuck-at faults and test inputs

**Prerequisites:** dl-02-06. **Covered by sets:** B 129 (brief). **GAP:** written from Abramovici,
Breuer and Friedman and Mano.

### Teaching sequence
1. **Radar** `#radar`; intuition `#fault-intuition` (a stuck switch: you only notice it when you
   try to set it the other way and look at a lamp that depends on it).
2. **The stuck-at model** `#stuck-at-model` (each line s-a-0 or s-a-1; single vs multiple faults);
   counting `#fault-count` (single: 2N; multiple: 3^N − 1); theorem `#fault-count-theorem` + proof;
   `:::trap` `#trap-multiple-count` (2^N, 3^N, 2N).
3. **Detecting a fault** `#test-vector` (a test makes the good and faulty outputs differ);
   activation `#activation` (drive the line to the opposite of its stuck value); propagation
   `#propagation` (side inputs at non-controlling values: 1 for AND/NAND, 0 for OR/NOR; XOR always
   passes a change); theorem `#test-condition` (t detects p s-a-v iff p(t) = v′ and f changes when
   p is flipped at t) + proof; the Boolean difference `#boolean-difference`
   (∂f/∂p = f|_{p=0} ⊕ f|_{p=1}); animated `fault-injection`.
4. **Undetectable faults** `#undetectable` (activation and propagation conflict; IT 2007);
   theorem `#redundant-undetectable` (a fault no input detects leaves the function unchanged, so the
   line is redundant) + proof; `:::trap` `#trap-none-of-above`.
5. **Test sets** `#test-sets` (every single fault of an n-input AND needs n + 1 tests; equivalent
   faults `#fault-equivalence`: input s-a-0 ≡ output s-a-0 on an AND).
6. **Live Lab:** none in this lesson (the chapter lab is in lessons 1–5).

### Derivations and proofs
- `:::theorem` fault counts + proof; `:::theorem` test condition + proof; `:::theorem` undetectable ⇒
  redundant + proof; `:::derivation` the n + 1 test set of an AND gate.

### Worked examples (4 per concept)
- **Finding a test:** an AND gate input s-a-0 (easy); the 1994 NAND chain (medium); a fault behind
  an OR gate (GATE); edge case: a fault on a fan-out stem reaching the output by two paths.
- **Counting faults:** single faults on 5 lines (easy); multiple faults on 3 lines by enumeration
  (medium); faults of a given circuit's lines (GATE, IT 2005); edge case: counting only faults
  that change the function.
- **Undetectable faults and test sets:** which of four vectors detect a fault (easy); test set
  for a 3-input NAND (medium); the IT 2007 circuit (GATE); edge case: a redundant consensus term
  whose s-a-0 fault no input can detect.

### Tricks and traps
- `:::trick` `#trick-activate-propagate` (set the line opposite, then make every gate on the path
  pass it); `#trick-noncontrolling` (AND/NAND side inputs 1, OR/NOR side inputs 0).
- `:::trap` `#trap-multiple-count`, `#trap-none-of-above`, `#trap-mask` (a test for one fault may
  mask under another).
